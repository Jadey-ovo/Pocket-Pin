# 调研计划：基于 Beadmaster 的 Pocket Pin 产品重构

> 本文为历史调研与候选方案，不代表当前已实现功能或工程授权。当前功能见 [PRD](PRD-Pocket-Pin.md)，未实现方向及决定状态见 [产品规划](产品规划-Pocket-Pin.md)。

调研日期：2026-10-19。状态：讨论稿，尚未转为已确认需求或开发承诺。

## 1. 结论与调研边界

建议将 Pocket Pin 定位为移动端拼豆创作与制作工具，围绕“找图或生成 → 编辑 → 备料 → 辅助开拼 → 完成归档”组织产品。保留现有图纸生成和编辑能力，补齐库存、制作任务、智能板和数据恢复能力。

本轮查看了拼豆大王官网实际可访问页面、App Store 产品介绍与更新记录，核对了 Pocket Pin 本地 PRD、生成算法说明、主要模块代码和历史验证记录。没有登录竞品账号，没有操作实体智能板；官网桌面页面所见入口不能等同于移动 App 完整体验。未验证的功能不记为已实测。

目标产品为 beadmaster.cn 对应的“拼豆大王”，App Store ID 为 6760411083；不与其他名为 BeadMaster、Bead Master 或“拼豆大师”的产品混淆。

## 3. Pocket Pin 的基础与缺口

项目当前已有 Vue 3、TypeScript、Vant 基础。根据文档和代码核对，可复用图片构图、卡通/照片两类处理、MARD 211 色匹配、Worker 生成、局部编辑、换色、减色、参考图、本地保存、用量统计及导出引擎。

需要澄清三个边界：

- 当前生成主要是图像处理和颜色量化，不能称为已具备语义理解、文生图或可靠 OCR。
- PDF、XLSX、JSON 等底层输出能力与实际界面入口需要分别核对，不能把引擎函数当作用户已能直接使用。
- 历史记录包含测试和尺寸模拟，真实手机/平板手势、性能和下载仍需本轮重新验收。

主要缺口是制作任务、库存账本、识别校对、智能板适配、账号同步和成品归档。单个 complete 布尔值不足以表达同一图纸多次制作，也无法记录每次消耗和进度。

MARD 211 色继续作为现有兼容基准。色卡核对文档明确其为公开屏幕参考数据，尚非厂商实物测量值；本轮不因竞品色数更多就自动扩色。新品牌、新系列和新材质应使用独立色卡版本，避免改变旧作品。

## 4. 新产品结构

### 4.1 产品定位

“把喜欢的图片，做成真正拼得出来的作品。”

生成质量、材料可得性、豆板容量和制作可读性共同决定结果。生成预览应能回答图案是否清楚、需要几块板、缺哪些色、能否减少材料负担。

建议手机一级导航为“工作台 / 图纸 / 创作 / 豆仓 / 我的”。创作页是稳定的任务入口，可再次进入草稿，而非点击即强制选照片。

| 入口 | 内容 |
| --- | --- |
| 工作台 | 继续制作、待备料任务、最近图纸、设备状态 |
| 图纸 | 我的图纸、合集与搜索；后续接入精选图纸 |
| 创作 | 照片生成、已有图纸识别、空白绘制、最近草稿 |
| 豆仓 | 色号库存、收纳位置、补货、账本 |
| 我的 | 成品集、备份同步、设备管理、偏好与帮助 |

设备连接状态在制作页持续可见。成品在工作台有快捷入口，在“我的”中集中管理。初期图纸页以个人管理为主，精选内容具备来源和授权后再上线。

### 4.2 主流程

选择来源 → 生成或识别 → 校对与编辑 → 保存图纸版本 → 建立制作任务 → 检查材料与板型 → 屏幕或智能板辅助 → 确认实际消耗 → 拍照归档。

“图纸”“制作任务”“成品”是三个关联对象。同一图纸可以做多次；修改原图不能悄悄改变进行中的任务。

## 5. 各模块升级方案

| 模块 | 建议升级 | 首期范围与后续范围 |
| --- | --- | --- |
| 工作台 | 以继续开拼为首要动作，直接显示剩余颜色、缺料、连接状态 | 首期完成；推荐和创作统计后续补充 |
| 图纸管理 | 搜索、合集、标签、批量操作、来源与版本；制作状态与备料状态分开 | 首期基础管理；复杂标签与套图管理后续增强 |
| 照片生成 | 保留简单默认流程；生成后比较原图与图纸，显示尺寸、用色、颗数、板数 | 首期升级；库存约束生成后续加入 |
| 已有图纸识别 | 网格校准、色号识别、低置信度定位、逐色或区域校对 | 独立研发验证后上线，不能直接复用照片量化充当识别 |
| 编辑器 | 保留已实现工具；基础工具常显，低频操作收纳；局部放大和修改预览 | 首期重组；轮廓与孤立豆辅助后续加入 |
| 备料计划 | 单图/多图/多份数量汇总，计算现有、预留、缺口；替色先预览再采用 | 首期单任务；多图汇总和批量计划随后升级 |
| 豆仓 | 手动与模板录入、搜索、袋/颗单位换算、收纳位置、调整原因和账本 | 首期核心账本；CSV/自然语言录入后续加入并需预览确认 |
| 辅助开拼 | 单色高亮、其他颜色淡化、坐标、分区、镜像、手动进度、断点续拼 | 首期核心能力，屏幕模式独立可用 |
| 智能板 | 支持型号检测、方向校准、尺寸校验、逐色/分区下发、状态与失败恢复 | 先验证一个型号；多型号和拼板取决于硬件能力 |
| 导出 | 清晰展示图片、可打印图纸、材料清单、编辑备份的用途 | 首期整理入口；A4 分页和实物比例校准后续增强 |
| 成品集 | 成品照关联图纸版本、任务、实际耗材与完成时间 | 首期简版；日历、展示墙和分享排版后续加入 |
| 保存与同步 | 本地自动保存、保存失败提示、可恢复备份；账号可选 | 首期本地可靠性；跨设备同步单独建设 |
| 发现与商业化 | 合法来源图纸、作者、难度、材料需求；以后再做交易 | 后续独立阶段，不作为首期主流程前置条件 |

### 5.1 库存规则必须先定义

库存用“实存、预留、可用”三个数量表达，可用量为实存减有效预留。加入计划不能直接扣实存；开启预留时明确展示影响。完成时先核对实际消耗，再一次性记账，允许不扣库存。

示例：H2 实存 1000 颗，任务 A 预留 600 颗，则任务 B 可用 400 颗。A 完成并确认消耗 600 颗后，实存变为 400，A 的预留释放。取消任务只释放预留。撤销完成生成对应冲正记录，避免重复扣减。

补货量按缺口和每色包装规格分别计算；安全余量是用户可设参数，不默认伪造精确材料需求。识别或自然语言导入必须先展示待入账清单。

### 5.2 辅助制作规则

制作开始时冻结图纸版本和板型。中途编辑可保存新版本，再明确选择是否重建任务及重新计算材料。逐色完成和逐区完成均由用户标记；点亮 LED 只代表显示指引，不能当作检测到已经放好豆子。

超过板尺寸的图纸先展示分块方案、方向和拼接位置。只有硬件验证支持后，才提供相应下发功能；不能等到全部编辑完才告知无法显示。

### 5.3 生成能力升级

建议在现有本地算法上，逐步加入可选的简化用色、关键色保护、库存约束和板型约束。用户能查看限制前后的差异，缺色替换不能静默改变人物肤色、眼睛或轮廓。

生成验收使用固定图片集，覆盖卡通细线、照片人物、宠物、植物、透明背景和近似色。用人工辨识度、材料数量及算法稳定性共同判断，不仅比较输出像素误差。AI 文生图、语义抠图等作为独立候选，另评估成本、隐私和输出质量。

## 6. 新设计风格与自适应

### 6.1 推荐方向：现代像素创作工具

整体使用中性浅底、清楚的层级和克制的色彩，让图纸成为画面中心。图纸和成品可以活泼，工具区域保持稳定、易读。

| 项目 | 建议起点 |
| --- | --- |
| 主背景 / 面板 | #F5F6F8 / #FFFFFF |
| 正文 / 次要文字 | #20242D / #626977 |
| 主强调色 | 钴蓝 #3155E7，用于主操作、选中态和焦点 |
| 圆角 | 输入与按钮约 10–12px，面板约 16px；后续统一为设计变量 |
| 字体 | 系统无衬线中文，色号和坐标使用清晰的等宽数字 |
| 图标 | 沿用项目现有 Tabler 系列，统一大小和线宽 |
| 动效 | 只帮助理解操作、面板和状态变化，尊重减少动态效果设置 |

这是一组视觉起点，文字、状态、选中边框与浅色豆子的辨识需在真实界面中检查。业务状态不能只靠颜色表达。移除动森主题的纸张纹理、木质装饰、厚重立体按钮和游戏式语言；保留舒适触控与轻松创作的感觉。

另两个可比较方向是黑白为主的专业工作室，以及中性底搭配珊瑚红的手作品牌。推荐先以钴蓝方向制作同一组关键屏幕比较，避免在多个页面混用风格。

### 6.2 手机和平板重新编排

| 场景 | 手机 | 平板 |
| --- | --- | --- |
| 全局导航 | 底部五入口，主操作在拇指可达区域 | 宽度足够时左侧导航；分屏变窄后回到紧凑布局 |
| 图纸列表 | 两列起步，文字缩放或窄屏时允许单列；筛选集中收纳 | 按可用宽度增加列数，可并排显示选中图纸详情 |
| 生成 | 构图、生成预览、确认按阶段进行 | 原图与生成结果并排，参数固定侧栏 |
| 编辑 | 画布最大化，底部工具和可调高度面板 | 左工具、中央画布、右色卡或属性；避免多层遮挡 |
| 制作 | 高亮画布与当前色号常显，大尺寸上一步/完成/下一步 | 同时显示总览、局部图、色号清单和设备状态 |
| 豆仓 | 按色号快速查找与增减，批量编辑单独进入 | 清单与详情并排，便于批量核对 |

布局按当前窗口可用宽度选择，而非只按设备名判断。横竖屏和分屏切换保留画布位置、所选色号、制作进度与未提交输入。触控目标至少 44px，长色号、软键盘、安全区和系统字体放大都需要覆盖。

## 7. 智能板与技术路线

Safari/iOS Safari 当前不支持 Web Bluetooth；Android Chrome 支持不代表 Android WebView 同样支持。因此当前 H5 不能直接承诺 iPhone/iPad 的蓝牙能力。[MDN 浏览器兼容数据](https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/Bluetooth.json)。Web Bluetooth 还依赖 HTTPS、用户主动发起授权和可访问的 BLE 服务。[Chrome 官方说明](https://developer.chrome.com/docs/capabilities/bluetooth)。

建议优先评估“保留 Vue 编辑和生成核心，增加移动应用原生蓝牙桥接”。它是待验证路线，尚未选定封装框架。验证范围包括 BLE、Canvas/Worker、OpenCV、文件导出、本地存储和系统生命周期，不能假设套壳即可全部正常。

智能板先做一个型号的技术验证：

1. 取得实际型号、固件版本、板格数和协议/SDK资料，优先联系厂商公开接入方案。
2. 在目标手机和平板测试发现、连接、发送单色点位与清屏。
3. 校验原点、旋转、镜像、行列顺序和边缘点位，确保不发生错位。
4. 验证连续换色、超时、断线、重新连接和切后台恢复，记录真实耗时。
5. 检查大图分块及硬件反馈能力；不支持的状态不在界面里假显示。

断线恢复时应保留本地任务状态，重连后可重新发送当前分区；只有协议支持时才承诺传输断点续传。兼容名单写明型号和固件，避免使用“所有智能板”表述。

产品模型建议新增图纸版本、制作任务、库存流水、预留和成品记录。设备层与图纸/任务分离，以统一能力接口适配不同硬件。账号同步后续按版本检测冲突，图纸可保留冲突副本，库存按流水去重合并，避免最后一次保存覆盖真实消耗。

## 8. 分期与验收

| 阶段 | 主要交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：验证与设计定稿 | 竞品核心流程补测、真实智能板验证、数据模型、手机/平板关键页与设计变量 | 硬件接入路径清楚；生成、备料、开拼能在原型中连贯完成 |
| B：重构基础闭环 | 新导航和视觉、生成编辑整合、图纸版本、屏幕辅助制作、基础豆仓、完成记账与归档 | 无设备也能完整制作；迁移、恢复和记账通过验收 |
| C：智能板产品化与效率 | 已验证型号接入、尺寸/方向校验、分区下发、断线恢复、多图备料、导出整理 | 目标 iPhone/iPad/Android 真机通过核心操作与异常场景 |
| D：识别、同步与内容 | 已有图纸识别校对、可选账号同步、授权精选图纸、创作者能力 | 识别错误可被发现并纠正；同步恢复可验证；内容来源明确 |

硬件技术验证在 A 阶段开始，不延后到界面全部完成。B 阶段可独立交付，但只有 C 阶段完成才具备本次目标中的智能板完整体验。识别与同步可提前做技术验证，不承诺未经验证的上线日期。

### 核心验收清单

- 老作品迁移前保留备份，尺寸、色号、透明格和原图可恢复；失败不覆盖旧数据。
- 同一任务重复点击完成、重试或恢复后，不会重复扣库存；取消任务正确释放预留。
- 一个图纸可多次制作，不同任务进度和消耗独立；编辑新版本不改变旧任务。
- 大于板容量的图纸在开拼前明确分块；角点、旋转、镜像的灯位与屏幕一致。
- 断网仍可打开本地任务和记录进度；断线不丢任务，恢复时状态可理解。
- 小屏手机、平板横竖屏、平板分屏均能生成、编辑、备料和制作；切换不清空草稿。
- 真实设备覆盖缩放误触、软键盘、后台恢复、文件下载、大图内存和低性能设备。
- 保存、同步和发送分别显示真实状态；没有成功回执或可靠验证时不展示成功。

建议指标为首次生成并保存成功率、生成到开始制作的转化、备料缺口确认率、设备连接与发送成功率、任务恢复成功率、重复记账错误及崩溃率。先建立当前基线，再设量化目标，不预先宣称性能提升。

不建议现在给固定总工期。主要变量是目标硬件资料和真机验证结果、识别方案、账号同步范围及团队投入。A 阶段结束后按可验证交付物估算。

## 9. 下一步设计交付

下一轮建议先做六组关键界面：工作台、图纸详情、生成预览、编辑器、备料与豆仓、辅助开拼。每组同时包含手机与平板布局，并覆盖空态、处理中、失败及恢复。

其中“图纸详情 → 建立任务 → 备料 → 开拼 → 完成记账”应连成可操作原型，再据此更新唯一主 PRD。本文保留为调研与方案讨论记录，当前不修改既有正式需求，也不改动应用和同步参考文件。

仍需补充的输入包括用户实际使用的智能板型号/固件、最满意的三项操作，以及愿意用于验收的典型原图和成品图纸。这些输入会影响硬件兼容目标与质量标准，但不阻碍先完成结构和视觉原型。
