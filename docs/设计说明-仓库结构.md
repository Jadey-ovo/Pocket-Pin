## 3. 现有模块及依赖

| 落点 | 当前职责 | 依赖边界与后续整理方向 |
| --- | --- | --- |
| `pocket-pin-client/src/app/` | 路由、入口样式 | 装配首页与编辑器；`/projects` 重定向首页。 |
| `src/core/` | 色卡、作品模型、默认值与旧数据归一化 | 模型供项目、编辑、识别结果保存使用；保持既有色号与旧作品兼容。 |
| `src/modules/projects/` | 作品列表、当前作品、本地保存状态 | 保留领域与存储职责；旧 ProjectsPage 未被当前路由引用，不据此扩展 PRD。 |
| `src/modules/home/` | 图纸空间、搜索筛选、作品操作、导出面板 | 当前 HomeExport 同时被编辑器引用，导出 UI 的所有权与复用边界需在后续移动前明确。 |
| `src/modules/studio/` | 编辑器、画布、照片构图、参考图、编辑运算及输出 | StudioPage 同时组织多类交互，后续可按照片流程、编辑会话和参考图拆分，但本轮不拆。 |
| `src/modules/chartImport/` | 识别向导、图例、网格、映射、校对 | 结果由首页或编辑器保存；识别模块不自行拥有作品列表。 |
| `src/shared/` | 通用外壳、色号选择、反馈、语言、匿名统计 | 现有色号面板反向依赖 studio 的拖动指令，未来提取通用能力时同时处理两侧消费者。 |
| 客户端 `qa/`、邻近 `*.test.ts` | 独立验收页面、单元与组件检查 | 保留现有位置，不为统一命名移动全部测试。 |
| 客户端 `build/`、根 `.github/` | 识别资源准备、检查与发布 | 方案整理不修改运行行为。 |

产品仓库不包含当前镜像同级的 `sites/pocketpin-events` 与 `sites/pocketpin-analytics`。客户端引用匿名统计入口，不代表这些独立服务归属本轮；不迁入、不修改、不新增服务实现。

## 4. 后续代码整理方案

本节是后续实施的边界建议，不是本轮实际改动。

- 导出 UI 若移出 home，优先明确其为跨功能模块能力，首页与编辑器统一引用；保留输出引擎，不同时重写渲染、下载和数据格式。
- 通用拖动能力若从 studio 提取，连同 ColorDock、共享色号面板等消费者一起调整；不新增第二份同逻辑指令。
- 未被路由使用的 ProjectsPage、旧 ExportPanel 及旧面板状态，先核对实际消费者和恢复需求，再决定保留或删除；不能仅因搜索不到一个路由就删除所有相关能力。
- 拆分 StudioPage 时，以当前用户行为为边界，保持操作取消/确认、撤销、图片生命周期和保存失败行为；不能在结构整理中顺带改变功能。
- 参考图恢复、保存失败提示与备份入口不一致属于功能缺口，需另行明确处理范围。本轮记录事实，不修改代码“配合文档”。

未来实施只检查当次受影响引用和消费者；涉及核心作品或输出兼容时补充对应验证，不将整仓重构作为 WF 的前置条件。

## 6. 不列为当前功能的具体依据

- `studio/ExportPanel.vue` 虽包含 PDF/XLSX/JSON 按钮，当前页面没有引用它；`exportFile`、`importJson` 与隐藏输入不等于用户可到达的入口。`leave()` 的保存失败文案仍建议 JSON 备份，但实际打开 HomeExport，缺少对应下载能力。
- `readSource/saveSource` 存在且被导入，当前 StudioPage 没有调用它们；首页复制已有原图的逻辑不能证明新照片已保存、可重开调整。
- `normalizeProject()` 只恢复部分 settings 字段，未恢复 `reference`；参考图当前编辑可用，不承诺网站重新加载后恢复。未将旧组件测试中的内存状态恢复当作跨刷新证明。
- 当前编辑菜单没有锁定、减少用色或显示设置入口，编辑器加载还会解除旧锁定；旧模板片段不构成当前功能。
- 校对页没有撤销和设为空白入口，不能把 `reassignCells` 可处理空值当作 UI 功能。未知图例数量归入不一致；图例数量只有输入框，未提供历史描述中的加减按钮。
- 当前普通选色没有“本图用色/最近”独立入口。图案边界导出、作者设置也未在实际导出面板提供。

上述内容转入规划并保留历史预期，不代表用户取消原目标，也不构成已授权修复。
